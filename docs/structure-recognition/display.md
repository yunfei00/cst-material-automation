# 手机屏幕总成几何识别（第一版，待真实工程验证）

> 状态：当前只有公开可复现的合成测试，没有任何公司真实手机工程数据。本算法只能输出可审计的**屏幕总成候选**，不能确认器件功能、材料或物料身份。2026-11-23 实机结果回来前，不得标记为“已验证屏幕识别”。

## 1. 识别目标与排除范围

目标不是判断“一个扁平 Solid 是不是屏幕”，而是在逐 Solid STEP 导出目录中寻找可能共同组成手机显示模组的 Solid 集合。显示模组可能包含盖板玻璃、触控层、OLED/LCD、支撑片、胶层、窄边框和排线；不同工程可能把它们合并为一个 Solid，也可能拆成多个 Solid。

第一版输出以下候选等级：

- `DISPLAY_CANDIDATE`：大面积、薄、接近整机正反外侧的板状候选；证据较弱。
- `PROBABLE_DISPLAY_MODULE`：除单体形态外，还存在投影高度重合、方向一致、厚度方向相邻的层叠成员。
- `STRONG_DISPLAY_EVIDENCE`：候选总成具有更具区分力的轮廓、孔槽、边框或排线等 B-rep 证据；仍需人工确认。
- `AMBIGUOUS_FRONT_BACK`：正反两侧存在无法仅凭几何可靠区分的候选，尤其是屏幕盖板与后盖玻璃。
- `OTHER`：不满足当前候选条件，或被已有结构证据排除。

明确不做：

- 不因 Solid 名称含 `screen`、`display`、`OLED`、`glass` 就确认屏幕。
- 不使用材料名、BOM、供应商、型号或公司样本尺寸作为纯几何条件。
- 不把单个大薄片直接视为屏幕；电池、后盖、石墨片、胶片和屏蔽片都可能具有相似外形。
- 不自动赋材，不修改 CST/STEP，不覆盖人工确认结果。

## 2. 输入、输出与代码入口

输入目录应来自当前逐 Solid 导出流程，至少包含：

- `geometry_features.sqlite3`：P5 几何索引，提供 Solid ID、STEP 相对路径、体积、面积、包围盒、面边统计等；
- 对应 STEP/STP：存在时执行精确 B-rep 检查，缺失时只能保留粗筛证据；
- 可选的既有识别报告：电池、PCB、屏蔽罩结果仅用于排除或降级，不能反向证明屏幕。

入口与产物：

- 模块：`src/cst_material/display_recognition.py`；
- 批量入口：`scan(folder, progress=None)`；
- 命令：`python -m cst_material.display_recognition <导出目录>`；
- 缓存：导出目录内 `display_recognition.json`；
- 查看器：`view_solids.py` 中“屏幕”筛选项；
- 测试：`tests/test_display_recognition.py`。

报告应保留算法版本、输入签名、排除上下文签名、实际使用的 `parameters`、是否完整、扫描/候选/失败数量，以及每个 Solid 的 `status`、`verdict`、`reason`、`evidence`、几何指标和可选 `assembly_id`。等级不是统计概率；第一版阈值只是合成几何起点，必须依据多机型正负样本验证后才能调整。

## 3. 为什么必须识别“总成”

当前电池算法已经明确记录：无特征的扁平长方体电池与 OLED 模组可能仅凭几何无法区分。前盖玻璃与后盖玻璃还可能是近似镜像。单体的长宽比、厚度、填充率只能证明“板状形态”，不能证明功能身份。

比单体更可靠的证据来自组合关系：

1. 屏幕覆盖整机长宽主体，且位于手机厚度方向的一侧外层；
2. 多个薄层主平面近似平行，二维投影高度重叠，中心接近，层间间隙很小；
3. 主面板周围存在窄边框，或短边附近存在与模组相连的薄长排线；
4. 轮廓包含圆角矩形、摄像头孔、听筒槽、刘海或局部缺口；
5. 候选与已识别电池、PCB、屏蔽罩的空间和拓扑性质不同。

即使以上证据同时出现，也只说明“很像显示总成”。真实身份仍需工程师、BOM 或组件信息确认。

## 4. 第一版算法层级

### 4.1 P5 廉价粗筛

先读取全部有效 P5 记录，拒绝缺失、NaN/Inf、非正体积和退化包围盒。对每个 Solid 计算：

- 三轴尺寸排序后的 `L >= W >= T`；
- 板状比 `T / sqrt(LW)`；
- 长宽比 `L/W`；
- 包围盒填充率 `V/(LWT)`；
- 大面投影面积及其相对当前工程最大值；
- 面、边、曲面类型等可用摘要。

粗筛应按面积与板状程度排序，而不是沿用电池“体积前 N 名”的策略。固定毫米值只用于数值容差；身份条件优先使用同一工程内相对量和无量纲比例。

### 4.2 朝向与整机外侧

模型可能任意旋转，不能假定全局 Z 就是手机厚度方向。存在 STEP 时，使用几何主方向或 OBB 法向；只有 AABB 时，最短轴仅作为弱提示。

第一版可以根据全部大件的共同主平面和整体包络估计设备厚度轴，并检查候选中心是否靠近该轴的两端。靠近外侧只提升候选级别；它不能区分前盖与后盖。

### 4.3 B-rep 精查证据

第一版对粗筛后的少量候选实际检查：

- 相对且面积占比较高的两个主平面；
- `sheet_thickness.analyze_sheet_faces` 给出的平面配对和主导厚度一致性；
- 平面内边界环数量，作为贯穿孔、槽或非对称开口的通用线索；
- 圆柱面数量，作为圆角侧壁的弱线索。

后续有真实数据后可继续实现：二维外轮廓连续性与圆角半径、孔槽位置、窄边框环绕关系，以及从边缘伸出的薄长排线聚类。第一版不会把这些尚未实现的特征写成已获得证据。

不是每台手机都具有孔槽或可见排线，因此缺少这些证据不能直接判 `OTHER`；只能保持较低等级。曲面屏、折叠屏和被高度简化的 CAD 可能无法通过平面规则。

### 4.4 层叠总成聚类

两个候选加入同一总成至少需要：

- 主平面法向近似平行；
- 投影轮廓或包围盒二维 IoU/覆盖率较高；
- 面内中心偏移相对自身尺寸较小；
- 厚度方向相邻，且没有明显交叉或远距离分离；
- 尺寸层级合理，小层不能仅因碰巧邻近就吞并大层。

聚类输出成员列表和逐成员证据，不尝试在第一版中把每层命名为玻璃、OLED、胶或背板。单层简化模型允许停留在 `DISPLAY_CANDIDATE`。

### 4.5 排除与降级

| 易混淆对象 | 排除/降级证据 |
| --- | --- |
| 电池 | 已有电池报告命中；位于内部；更厚；存在电池算法的双侧 U 形槽证据 |
| 主 PCB | PCB 域或 PCB 候选命中；内部位置；孔和轮廓复杂；器件承载板特征 |
| 屏蔽罩 | 低填充率、开底空腔、薄壁侧墙或既有屏蔽罩强证据 |
| 中框 | 深腔、侧壁、翻边、大量安装结构，非单纯层叠薄板 |
| 后盖 | 与前侧候选近似镜像且缺少可区分孔槽/排线；返回前后歧义 |
| 石墨片/胶膜 | 极薄、位于内部、覆盖不足或缺少外侧/层叠/轮廓证据 |
| 摄像头盖玻璃 | 面积相对整机明显过小，不能成为主显示面板 |

已有识别报告只能作为独立证据。报告缺失、版本过旧或缓存签名不一致时不得静默当作“已排除”。

### 4.6 前后盖歧义

如果设备厚度轴两端各存在近似等强度的大面积薄板，且两者都没有孔槽、排线或其他非对称结构，纯几何无法可靠判断哪侧是屏幕。此时必须：

- 输出 `AMBIGUOUS_FRONT_BACK`；
- 同时保留两侧候选，不按面积微小差异强选一个；
- 在查看器中让工程师分别检查；
- 可在独立业务确认层使用 BOM、组件名或人工标记，但不能把该信息伪装成纯几何结论。

## 5. 数据流

```text
geometry_features.sqlite3
  → 校验全部有效 Solid
  → 相对面积 + 板状程度粗筛
  → STEP 可用时计算 OBB/法向、厚度和轮廓证据
  → 读取有效的既有类别报告进行排除/降级
  → 依据平行、投影重叠、中心和层间距聚类
  → 判断外侧位置与前后对称歧义
  → 输出逐 Solid 证据、总成候选、摘要和完整缓存
  → PySide6 查看器筛选并人工确认
```

昂贵 B-rep 操作只对粗筛候选执行。缓存必须绑定算法版本、P5/STEP 输入签名及结果完整状态；中断或损坏的缓存不能冒充完成结果。

## 6. 误报、漏报与安全边界

主要误报来源：平面后盖玻璃、内部石墨片、超薄电池封装、面积较大的屏蔽/散热片。主要漏报来源：曲面屏、折叠屏、单一合并实体、只有显示有效区而无盖板、STEP 丢失装配位置、CAD 过度简化或局部坐标未还原。

第一版策略是**准确性优先**：宁可返回候选或歧义，也不输出几何无法证明的确认结论。后续不能为某一个公司样本添加固定尺寸、名称白名单或特定 Solid ID；阈值调整必须覆盖多机型正负样本。

## 7. 性能、可追溯性与隐私

- P5 粗筛应在 SQLite 只读模式下完成，不修改数据库。
- STEP 只在本地读取，不复制、不上传；报告只保存几何摘要和相对路径。
- 每个候选保留通过/失败阶段、证据、排除原因、总成成员、耗时和缓存命中状态。
- 原 CST 和 STEP 不作为写入目标；报告仅写入导出目录。
- 公司 Solid 名称、路径、几何尺寸和截图不得提交到公共仓库或公开 issue。

## 8. 测试与真实验收

合成回归至少覆盖：旋转和平移后的圆角薄板、单层与多层、双侧对称板、孔/槽/缺口、排线形态、缓存失效、损坏输入，以及电池、PCB、中框、后盖、屏蔽罩和普通薄片负例。

真实验收先使用 3～5 个工程做数据审计，再积累至少 20～30 个已确认显示总成和更多强负样本。重点指标不是“命中几个”，而是：

- Top-K 是否包含真实屏幕总成；
- 非屏幕误报数量及具体类别；
- 总成成员是否多收或漏收；
- 前后歧义是否诚实保留；
- 首次扫描耗时、缓存复用时间和失败数量。

完整步骤见 [手机屏幕识别实机验收](../display-recognition-verification.md)。
