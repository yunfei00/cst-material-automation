# 螺丝几何识别算法（v29 冻结基线）

> 状态：当前零件验证通过；本文件描述实际实现，不将 CI 视为全品类准确率证明。冻结基线提交 `9ae27ccc2da2f3e47fbc85ac2f4bee550ca8e4fb`，整理分支不改变识别逻辑。

## 1. 目标与边界

从 CST 工程逐 Solid 导出的 STEP/STP 三维 B-rep 几何中，识别**具有独立头部、实心同轴杆部、真实建模外螺纹**的螺丝。算法不依赖零件名、组件路径、BOM、材料名称、历史样本、固定尺寸或特定文件；不根据相似度或样本编号决定类别。当前实现的输出类别名是 `PHILLIPS_SCREW`，但**没有可靠的十字槽形状强制验收**，因此不能把该标签解释为已确认十字槽；它实际表示满足当前几何螺丝条件的零件。

不包含：仅用纹理/标注表示的螺纹、未建模牙型的光杆、内螺纹孔、仅靠名称判断的紧固件；对于不确定件返回 `OTHER`，不猜测。镜头筒等带外螺纹零件需要通过螺纹位置、头杆结构、实体轴心和截面牙型共同排除。

## 2. 入口、代码与数据流

- 入口：`src/cst_material/phillips_screw_recognition.py` 中 `recognize_step(path)`；批量扫描使用 `scan(folder, ...)`，命令行入口 `main()`。
- 测试：`tests/test_phillips_screw_recognition.py`。
- 输入：单个 STEP 文件；使用 `read_step` 获取 OpenCascade/OCP 实体。
- 输出：`verdict`、`score`、`evidence`、`axis`、`cylinder_count`、各阶段判定、螺纹与材料等证据。判定 `PHILLIPS_SCREW` 或 `OTHER`；`score` 当前为二值 100/0，不是统计概率。

流程：

```text
STEP B-rep
  → 提取面类型/面积/圆柱及圆锥轴向
  → 选取主要轴向
  → 检查主体圆柱面共轴
  → 确定头部与杆部（不同半径、同轴）
  → 轴向轮廓确认只有一端为头部
  → B-rep 实体分类器检查杆部轴心为实心
  → 精确 B-rep 轴向截面提取牙型
  → 扫描原始 B-rep 边并独立验证螺旋
  → 逐条检查螺纹位置、相位、牙型、径向起伏、外侧实体
  → 原始边均未通过时，尝试短片段重建并重复检查
  → 全部条件成立才输出 PHILLIPS_SCREW
```

## 3. 结构判断

### 3.1 主要轴线和共轴

遍历圆柱面、圆锥面，以轴向关联的曲面面积选择主方向。使用 `_common_axis_cylinders` 比较轴线方向和空间偏移；不仅判断平行，还要求轴线落在同一空间直线上。过滤较小的圆柱特征，避免局部孔壁、圆角干扰主体结构。

### 3.2 头杆分区

`_identify_head_shaft` 从圆柱面中选择较大的头部圆柱，以及同轴且半径较小的杆部圆柱。`_single_head_profile` 把网格点投影到主轴上，通过两端的径向包络判断是否只有一端具有头部特征；不允许两端都被当成大头。头部半径、杆部半径来自当前几何测量，不使用已知样本尺寸。

### 3.3 实心轴心

`_solid_axis_core` 沿杆部轴心选取多个内部位置，使用 OCP 的 `BRepClass3d_SolidClassifier` 检查这些位置是否属于实体内部。带轴向贯通孔的空心筒体不能仅靠外轮廓伪装为实心杆。

## 4. 真实外螺纹判断

### 4.1 精确截面

`_thread_surface_evidence` 以主轴为基准构建多个不同方位的轴向剖切平面，使用 `BRepAlgoAPI_Section` 提取截面曲线并采样径向轮廓。仅有一条形似螺旋的边不够，必须与实体截面上的牙型共同成立。

### 4.2 原始边优先：防止拼接污染

`_brep_thread_evidence` 遍历 B-rep 边，先按杆部半径附近的径向范围过滤，再采样曲线，剔除轴向高度近乎不变的环边。对**每条原始边**先调用 `_helix_from_curve_points`，验证角度展开、圈数、半径稳定性、轴向高度与角度的线性拟合、导程及残差。

验证成功的原始螺旋边直接保留，**绝不送入片段拼接**。这是 v28/v29 的关键修复：旧流程可能将有效螺旋边和相邻非螺旋边误拼，导致拟合圈数骤降而漏报。

### 4.3 逐候选验证

每条完整螺旋候选必须依次通过：

1. `_helix_on_shaft`：基于整个轴向包络判定螺纹位于杆部、不是头部；避免将镜头头部外螺纹误判为螺丝。
2. `_thread_phase_consistency`：验证不同截面牙型与螺旋相位关系，排除无相位推进的环槽。
3. `_thread_tooth_flanks`：检查真实牙侧轮廓及其与螺距的对应关系。
4. 牙高约束：根据实测截面起伏推导可接受的牙顶半径，不把任意大直径筒体当作杆部牙顶。
5. `_external_thread_material`：检查外螺纹的实体材料证据，避免只靠几何线条判定。

只要完整原始边全部未通过**下游检查**，仍允许对未通过原始螺旋检查的片段调用 `_join_helix_segments`，并重复上述全套验证。不能因为找到一条完整螺旋边就跳过其他可能的有效螺纹。

### 4.4 片段重建的限制

`_join_helix_segments` 只连接端点接近、切向方向基本一致的短边；重建结果仍必须通过完整螺旋及下游牙型检查。当前代码对片段数量设有上限，超过时不尝试重建；对极度碎片化、单边不足一圈的真实螺纹仍存在漏报风险。这是待评估的通用算法边界，**不是针对任何已知零件的例外**。

## 5. 与镜头筒、环槽、空心件的区别

| 易混淆结构 | 必要排除证据 |
| --- | --- |
| 镜头头部外螺纹 | 螺纹位于头部包络区域，不属于独立细长杆部 |
| 空心镜筒/套筒 | 杆部轴心实体分类不通过 |
| 多圈环形槽 | 截面牙型虽可能重复，但没有一致的轴向螺旋相位 |
| 仅有螺旋装饰线 | 缺少与 B-rep 真实截面牙型和实体材料一致的证据 |
| 无建模螺纹的光杆 | 无真实外螺纹，不能因为有头杆轮廓就判断为螺丝 |
| 偏轴组合件 | 主体圆柱面的空间共轴条件不通过 |

以上是组合判据，不代表任一单项足以识别所有零件。

## 6. 关键参数与非样本化原则

代码仍存在数值容差、采样数量、最小圈数、片段数量上限、径向预过滤范围等**算法级参数**。它们用于数值稳定性和性能控制，不应被解释为某个已知螺丝的直径、螺距或型号；也不应把现场反馈中的尺寸、圈数直接写成生产识别特例。后续参数调整必须进行多尺寸、多螺距、多建模方式的回归验证。

当前算法不保证所有实际螺丝均能识别：未建模牙型、边界严重碎片化、特殊头型或异常 B-rep 都可能返回 `OTHER`。

## 7. 性能与可追溯性

批量扫描支持多进程与基于文件摘要的结果复用。昂贵的 B-rep 截面与边采样仅在主体结构条件通过后执行；避免在每个 Solid 上执行全量面-边邻接二次复杂度诊断。性能必须以实际全量扫描耗时及误报漏报共同评价；此前曾出现约 4 分钟到 20 分钟的回退，不能以 CI 绿色代替全量性能验收。

建议保留：每个 Solid 的最终类别、失败阶段、头杆结构证据、原始螺旋边数量、拼接候选数量、牙型/相位/实体材料检查结果、扫描耗时及缓存命中信息。不得记录任何针对具体零件的硬编码识别结果。

## 9. 维护约定

每新增一种结构件识别器，都在 `docs/structure-recognition/` 下建立独立文档，按统一目录模板记录：目标与排除范围、输入输出、几何不变量、算法流程、实现函数、误报漏报、参数边界、性能、测试与版本历史。识别类别与材料赋值严格分离；几何不能证明材料身份。
