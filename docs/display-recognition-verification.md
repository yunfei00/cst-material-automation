# 手机屏幕总成识别：2026-11-23 公司实机验收手册

> 本手册验证第一版候选算法。当前没有任何真实公司数据，自动测试通过也不代表能正确识别真实手机屏幕。本轮目标是取得可脱敏的结构统计、误报原因和性能数据，不要求一次达到生产准确率。

## 一、验收前提与数据安全

在公司授权 Windows 电脑本地执行。不要上传 `.cst`、STEP、数据库、报告、截图、Solid 名称、真实尺寸或本机路径。反馈只提供数量、候选等级、耗时和脱敏后的误报类别。

优先准备 3～5 个已知结构的手机工程，尽量覆盖：

- 普通直屏；
- 圆角屏、刘海屏或打孔屏；
- 单 Solid 简化屏幕和多 Solid 显示总成；
- 平面玻璃后盖；
- 至少一个难例，如曲面屏、模型任意旋转或装配层较多的工程。

工程师需要能人工指出真实屏幕相关 Solid，但不必把名称发回仓库。

## 二、更新代码并运行自动检查

在仓库根目录打开 PowerShell：

```powershell
$ErrorActionPreference = 'Stop'
git switch main
git pull --ff-only origin main
uv sync --group dev --extra viewer
uv run ruff check .
uv run --extra viewer pytest tests/test_display_recognition.py -q
```

任何一步失败先停止，不继续扫描真实工程。测试成功只证明输入校验、候选分级、缓存和合成几何回归，不证明真实准确率。

## 三、准备逐 Solid 导出目录

如果已有完整导出目录，并且其中包含 `geometry_features.sqlite3` 与可读取的 STEP，可直接使用。否则按 [逐 Solid STEP 全量导出操作手册](per-solid-step-export-guide.md) 与 [P5 几何特征库操作手册](geometry-feature-library-p5.md) 完成导出和索引。

示例路径仅作占位：

```powershell
$geometryDir = 'D:\CST\Phone01.solid_export_diagnostic'
if (-not (Test-Path "$geometryDir\geometry_features.sqlite3")) {
    throw '缺少 geometry_features.sqlite3，请先完成 P5'
}
```

建议先复制整个导出目录作为验收副本。识别器不修改 STEP/数据库，但会在目录中生成或更新 `display_recognition.json`。

## 四、命令行扫描

```powershell
uv run --extra viewer python -m cst_material.display_recognition $geometryDir
```

预期：

- 控制台逐行显示阶段、进度、匹配与完成事件；
- 目录中生成 UTF-8 `display_recognition.json`；
- 报告标记 `complete: true` 后才可用于验收；
- 单个 STEP 失败应计入失败数量，不应使整个报告伪装成全部成功；
- 再次运行且输入未变时应复用完整缓存。

不要手工修改报告来制造命中。若需要强制重算，可先把旧报告移动到仓库外的备份目录，再运行；不要删除或覆盖原始 STEP。

## 五、查看器人工核对

```powershell
uv run --extra viewer python view_solids.py $geometryDir
```

在左侧勾选“屏幕”。预期只显示屏幕候选或前后歧义项，并在界面展示候选等级、原因和证据。逐项点击三维预览，人工判断：

1. 真实屏幕是否出现在候选中；
2. 多层屏幕成员是否被归入同一总成；
3. 后盖是否被错误判为更强的屏幕证据；
4. 电池、PCB、屏蔽罩、中框、石墨片是否误入；
5. 正反无法区分时是否显示 `AMBIGUOUS_FRONT_BACK`，而不是武断选一侧。

查看器筛选不等于人工确认，不触发材料赋值，也不修改 CST/STEP。

## 六、逐工程验收表

每个工程独立填写一行，不记录真实文件名或尺寸：

| 编号 | 检查项 | 通过条件 |
| --- | --- | --- |
| D-01 | 输入保护 | 原 CST、STEP、P5 数据库时间与内容未被修改 |
| D-02 | 报告完整性 | `display_recognition.json` 可解析、版本存在、`complete=true` |
| D-03 | 全量计数 | 报告扫描数量与 P5 PASS 记录数量一致或有明确候选上限说明 |
| D-04 | 真实屏幕 Top-K | 人工确认的屏幕至少出现在候选列表；未出现则记录漏报阶段 |
| D-05 | 单体理由 | 每个候选都有可理解的面积、薄度、位置或 B-rep 证据 |
| D-06 | 总成聚类 | 多层模型的成员组合合理；多收和漏收分别记录 |
| D-07 | 前后盖 | 无法区分时返回歧义；不能只因面积略大确认前侧 |
| D-08 | 电池负例 | 电池不被提升为强屏幕证据；既有电池报告的排除行为可追溯 |
| D-09 | PCB/屏蔽罩负例 | 已知 PCB、屏蔽罩不被错误确认成显示总成 |
| D-10 | 中框/后盖负例 | 深腔、侧壁、翻边或后盖结构得到排除/降级或歧义 |
| D-11 | 极薄内部片 | 石墨片、胶膜等没有仅凭薄度成为强证据 |
| D-12 | 旋转模型 | 不依赖固定全局 Z；任意朝向仍能形成合理候选或明确失败 |
| D-13 | 缓存 | 第二次运行结果一致且明显更快；输入变化后旧缓存失效 |
| D-14 | GUI | 勾选/取消“屏幕”可过滤和恢复列表，无卡死或残留错误状态 |
| D-15 | 失败安全 | 无法判断返回候选/歧义/OTHER，不自动赋材、不修改工程 |

## 七、正负样本审计清单

### 正样本形态

- 单层大盖板；
- 盖板 + OLED/LCD + 背板的多层结构；
- 圆角矩形；
- 刘海、听筒槽、打孔或局部缺口；
- 带窄边框；
- 带短边排线；
- 曲面边缘或折叠结构（预计第一版可能漏报，应记录而非临时放宽）。

### 必须核对的强负样本

- 平面玻璃后盖；
- 当前已识别电池与其他大面积电池封装；
- 主 PCB、副板；
- 中框、外壳和带侧壁深腔结构；
- 屏蔽罩、散热板、石墨片；
- 胶片、防水膜和普通超薄片；
- 摄像头盖玻璃及其他面积较小的透明件。

同一个工程缺少某类负样本不算失败；在累计验收汇总中注明“未覆盖”。

## 九、首轮结果如何决策

- **可以继续加强**：真实屏幕稳定进入 Top-K，主要问题只是候选过多或成员聚类不准。
- **需要调整粗筛**：真实屏幕完全不在候选中；先检查 P5 数据、朝向和相对面积，不直接写样本尺寸特例。
- **需要加强排除**：屏幕能找到，但后盖、电池、石墨片大量误报；增加通用空间/拓扑证据和负例测试。
- **数据本身不足**：STEP 丢失装配位置、屏幕与后盖完全对称或模型只保留无特征薄板；保持 `AMBIGUOUS_FRONT_BACK`，转入 BOM/组件名/人工确认层。
- **不得宣称通过**：只验证一个工程、只看一个命中、没有检查后盖等强负样本，或报告不完整。

完成首轮后，将脱敏反馈用于新增通用回归。任何阈值变化都应说明几何理由，并同时验证正例、后盖、电池、PCB、中框和屏蔽结构。
