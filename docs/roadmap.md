# CST 材料自动化研发路线

## 输入约束（已确认）

- 只有**一个已经包含三维结构与材料定义的 CST 工程**（`.cst`）。
- 不导入 SAT / ACIS，不导入外部材料库，不新建空工程。
- Windows 已安装 CST Studio Suite 2025 SP1，Python `import cst` 已验证；不再重复环境探测。

## P1/P2（2026-11-12 真实 CST 工程验收通过）

- **P1 — `inventory`**：绕过 Windows 中文工程树中的 `get_tree_items()` UTF-8 解码问题，使用 CST 2025 VBA 直接枚举 Solid/Material 和当前材料关联。
- **P2 — `assign`**：确认 Solid 和材料存在（兼容 `Material.Exists` 返回 `-1`），对工程副本赋材、保存并重新打开核对。
- **证据：** 用户确认 P1 和 P2 在公司 CST 2025 SP1 实机 PASS；模拟 CI 仅用于回归。
- 运行流程见 [P1/P2 中文说明](p1-p2-verification.md)。

## P3（本分支：只读最小闭环，2026-11-12 用户确认实际执行通过）

- **P3-A `geometry`**：提取体积、表面积、长度单位及 SI 换算和紧致度；只用已在官方帮助中查到的 `Solid.GetVolume` / `Solid.GetArea` / `Units.GetUnit` / `Units.GetGeometryUnitToSI`。
- **限制：** 官方明确 `Solid.GetLooseBoundingBoxOfShape` 不能在 History/结构宏执行；当前 `add_to_history` 不能用于该接口。因此暂不实现包围盒、空间坐标、尺寸和邻接关系，不伪造特征。
- **P3-B `scan-mtd`**：外部 MTD 材料库只读文件级索引（路径、候选名称、大小、时间、SHA256），不解析物性，不批量导入 CST。
- [P3 使用与验收说明](p3-geometry-mtd-verification.md)。**用户报告 P3-A、P3-B 均通过实际运行**；但现有几何输出只覆盖体积/表面积，MTD 扫描只覆盖文件元数据，不代表包围盒、空间特征、MTD 物性读取已通过。

## P3-C（用户已确认空间读取与文件锁诊断通过）

- **P3-C `spatial`**：经 CST 官方 OLE `CSTStudio.Application.2025`、`Project.RunScript` 的命令宏路径尝试调用 `Solid.GetLooseBoundingBoxOfShape`，避免 History 限制。提供**非紧包围盒**、轴向范围、包围盒中点与包围盒邻近候选；不表示真实质心、厚度或真实实体接触。
- **状态：** 用户已确认 P3-C 实际运行通过；曾遇到 `result/dp.parmap` 的 WinError32 临时文件占用，已实现 Windows Restart Manager 只读根因诊断并完成本机回归。仍不能据此证明所有文件锁问题在所有工程中彻底消失。
- [P3-C 空间特征使用与验收](p3-spatial-probe-verification.md)。

## P3-D（离线邻近分析：用户反馈运行已正常）

- **P3-D `spatial-offline`**：读取以前的 P3-C 报告，不启动 CST；NumPy 分批处理非紧 AABB 距离下界，避免构建完整 N×N 距离矩阵，保留最近 5 个候选与稳定重叠排序。
- **测试与反馈：** 已通过 7,311 个合成 Solid 的规模/正确性测试，用户反馈修正 PowerShell `$input`→`$inputFile` 后命令正常执行。具体真实工程计数摘要未提供，保持此验证边界。
- **说明：** [P3-D 7,311 Solid 离线分析](p3d-large-neighbors-verification.md)。

## P4-A（已开发：离线结构候选，待真实报告验收）

- **命令：** `structure-preview`，读取 P3-A 与 P3-C 的 JSON（可附 P3-D 最近邻），按 Solid 标识、源路径、单位和已有材料进行一致性核对。
- **结果：** 体积/表面积、非紧 AABB 三轴范围、邻近候选与启发式形态类别（扁平盒、细长盒、三轴相近盒及其他）；输出判断依据，所有 Solid 的材料推荐均为 `null`，需要人工确认。
- **自动测试：** 7,311 个合成 Solid 完整处理；输入损坏、跨工程混用、邻近距离不一致全部拒绝。公司真实 P4-A 报告尚未验收。
- [P4-A 结构识别中文验收](p4a-structure-preview-verification.md)。

## P4-C：结构导入后的辅助件清理预览（代码和 CI 已完成，真实审查待执行）

- **只读命令：** `cleanup-plan`：P1 inventory + 可选 P3-A geometry，输出名称复核提示、体积为零的对象统计、人工显式选定的删除候选、必须保留对象及变体组规则。不连接 CST，不执行删除。
- **用户确认规则 R001（2026-11-12）：** P3-A 读取的 **`volume_project_unit3 == 0` 全部列入删除列表**，不区分 A>0/A=0、材料与名称。非零体积 Solid 不因该规则删除。与 `protected_ids` / 变体 keep 冲突时拒绝模糊执行。
- **副本实删入口：** `cleanup-apply` 使用官方 CST 2025 `Solid.Delete`，仅对新 `.cst` 副本批量执行，重新打开并核对完整剩余 Solid/材料；CI 只模拟接口，真实 CST 删除尚待验证。
- **规则 R001 不需逐项再确认**。其他规则仍需完整 Solid ID 和变体 keeper。官方 CST 2025 帮助已确认 `Solid.Delete(solidname)` 接口；保留首次非生产副本实机验证以及保存/回读一致性检查。
- **说明：** [P4-C 结构清理复核与零体积分类](p4c-cleanup-review.md)。

## 路线图更新（2026-11-13：三维 Solid 查看器 + 真实身份识别）

> **产品定义**：输入一个已有结构的 CST 工程；程序自动提取和识别 Solid，匹配已确认材料，在新工程副本执行赋材和已确认的结构清理；提供独立桌面三维界面，支持逐 Solid 检索和人工确认身份。该节是审阅计划，非完成声明。

### 1. 固定的产品原则

- **一个业务入口**：最终提供 `process_project(input_cst, output_cst)` 两个必需参数。原来的 P1/P3/P4 等报告和技术命令只作为内部模块/调试手段，不要求使用者事先运行一串工具或提供中间 JSON。
- **输入 .cst，输出新的 .cst**；不覆盖原工程；自动生成日志和失败原因；未完成实体/材料回读不得标记 PASS。
- **R001 已确认**：实测体积 V=0 的全部 Solid 删除；真实删除的 CST 实机验收仍未完成；不再围绕这条规则反复确认。
- **身份识别与材料赋值分离**：几何相似 ≠ 真实零件身份；识别不确定就标记 UNKNOWN，不盲目赋材。材料规则还要区分“器件整体”和“子结构”的材料。
- **全部离线**：公司 CST、STEP、BOM、材料文件和几何结果不上传公共仓库或云端 AI；只提交代码与合成测试。
- **性能以真实工程数据为准**：不假定 OCP 处理所有实体都快，也不承诺 7,000+ Solid 同时渲染一定流畅。

### 2. 技术架构与桌面方案

| 模块 | 选型 | 用途 |
| --- | --- | --- |
| CST 适配层 | 已有 CST 2025 Python + VBA/OLE | 批量读取、导出、清理、材料赋值、保存副本 |
| 精确几何分析 | Open CASCADE（OCP / cadquery-ocp） | STEP/B-rep 解析、拓扑/曲面分析、精确点包含和几何匹配 |
| 三维渲染 | **PyVista + VTK** | 将 CAD 几何三角化为可显示网格，旋转、缩放、拾取、剖切 |
| Windows 桌面 GUI | **PySide6 + PyVistaQt** | 工程列表、Solid 搜索、三维查看和人工审核 |
| 缓存与索引 | 本地几何缓存 + 元数据/空间索引 | 重复查看无需启动 CST，也无需反复解析 STEP |
| 识别引擎 | 几何规则 + 装配关系 + 已知零件样本 | 从几何候选逐步提高真实器件识别覆盖率 |
| 材料映射 | 已确认材料知识 + 原工程 Material | 子结构级别准确匹配，避免直接猜电磁参数 |

**为什么暂不选 Electron**：现在的业务、CST 接口和 OCP 都是 Python。PySide6 可以减少 Python ↔ Node 双进程通信与部署复杂性。未来确需 Web/跨机器查看时，再复用网格缓存与身份元数据开发 Three.js 视图，不必现在同时做两套。

**重要的双数据层设计**：

- **精确层**：STEP/原生 B-rep 缓存，供几何特征、拓扑、点内部/外部判断、几何相似度使用。
- **显示层**：三角网格缓存（VTP 等）供 VTK 快速绘制、选中、隐藏和高亮；必须保留 `mesh → 原始 Solid ID` 的关联，不能用可视化网格代替精确 CAD 几何。
- **身份索引**：每个 Solid 保留完整 `Component:Solid`、源工程版本指纹、单位、全局位置/实例变换、CAD 几何 hash、原材料、bbox。绝不按 STEP 导出后的实体排列顺序推测 Solid ID。
- **高风险前置验证**：CST 导出完整 STEP 装配是否保留各 Solid 的名称、实例坐标及层级，目前尚未实机证明；若丢失身份，改为逐 Solid 或分组导出并自动生成映射清单。

### 3. 新的开发顺序（先 POC，再扩展）

#### M1 — 离线精确几何与点包含验证（当前基础）

输入：真实 CST 中选取的 **5～20 个不同类型 STEP Solid**，包含弹片、平板、壳体、带孔或凹槽的实体。

- 使用已有 PR #10 `check_point.py`，验证真实 STEP 解析是否成功、封闭与有效、坐标/单位是否一致。
- 对已知内部、表面、外部的点返回 `INSIDE`、`ON_BOUNDARY`、`OUTSIDE`；先测简单实体，再测真实复杂实体。
- 分别记录首次解析、缓存重载、单点和 1 万点批量查询的耗时，以及内存峰值。性能必须与现有 CST 查询方式公平对照。
- **验收**：真实几何导入和坐标结果可重复、失败情况可诊断；合成长方体测试通过不等于真实弹片已验证。

#### M2 — PySide6 单 Solid 三维查看器 POC（**下一阶段优先开发**）

输入：**一个 STEP/STP 文件**（不需要连接 CST 或提前导入完整工程）。

- 用 OCP 读取精确实体并三角化；PyVistaQt 负责 VTK 窗口显示。
- 最小交互：旋转、缩放、平移、重置视角；点击选中 Solid 并高亮。
- 在界面中输入 X/Y/Z：显示三维点的位置，并调用 OCP 精确分类器显示内部/边界/外部状态；可切换查看包围盒、体积、面/边等基础属性。
- 记录 STEP 读取耗时、第一次显示时间、操作时延、峰值内存/显存；出现复杂模型异常时能明确提示。
- **验收**：真实弹片 STEP 外观和位置正确、鼠标交互正常、点标记与精确判断一致；工程师认可日常使用速度。**本阶段不识别弹片，也不修改 CST。**

#### M3 — 多 Solid、完整工程索引与三维浏览

输入：一个原始 CST 工程；内部自动导出精确几何并构建轻量显示缓存，不要求用户手工导出成千上万份 STEP。

- 验证装配 STEP 是否保留原始 ID；不保留就使用逐 Solid/分组的自动导出机制 + 校验清单。
- GUI 左侧 Solid/Component 列表可搜索；中间显示单件或所在区域；右侧查看位置、体积、几何特征与材料。
- 支持 **Solid 列表→三维模型** 与 **三维点击→Solid ID** 双向联动、选中高亮、隐藏、隔离、相邻件显示。
- 只在需要时加载可视化网格；整机概览用分组/LOD/渐进加载，减少数千独立 Actor 和重复几何解析。
- **分级验收**：先 50 个、再 500 个、最后真实 7,000+ 个；记录首屏时间、搜索与选中延迟、帧率和内存。随机抽样核对精确 Solid ID，不可错位或串件。

#### M4 — 真实器件身份识别 POC（首先做弹片）

- 第一批用工程师确认的弹片（建议 20～30）和易混淆的非弹片（建议 30～50）建立独立验证数据；数据量后续根据结果调整。
- 第一层：薄壁、厚度、长宽比例、面/边、曲面/折弯、悬臂等 CAD 特征做候选筛选。
- 第二层：与已确认 CAD 零件几何匹配、与 PCB/中框/连接区域的空间关系、同器件多 Solid 聚类。
- 第三层：如有可靠的原始 CAD 名称、BOM 或物料号，优先匹配实物身份；没有证据时必须允许 `UNKNOWN`。
- 三维界面直接高亮识别对象，展示判定依据、候选标签和人工确认入口；确认结果进入本地知识库。
- **验收**：独立留出测试样本上统计精确率、召回率、识别覆盖率及误判；不能仅凭“能显示弹片”就宣称“能自动认出弹片”，也不承诺未经验证的 95%/100% 准确率。

#### M5 — 已确认材料匹配与完整输出闭环

- 把已确认的器件身份、**子结构身份**对应到原工程已定义的材料；金属类别不自动等价为某种确定电导率材料。
- 基于已确认的 R001 清理规则和材料匹配表，在新 CST 副本赋材，保存并重新打开验收。
- 输出清理明细、身份识别证据、已赋材料、未知项及失败原因；新模型的端口/边界/网格/仿真有效性需另行核查。
- GUI 保留人工审阅功能，但 **核心 Python 入口不依赖 GUI**。
- **验收**：已确认样本材料一致、CST 新工程能打开、剩余 Solid 和材料映射全量回读匹配、原工程未改变。

### 4. 当前真实状态，不将计划误写为完成

- **已经有实机验收基础**：P1/P2 的读取与赋材、P3-A 体积面积、P3-C 空间包围盒；P3-D 离线邻近运行过。
- **已有代码但不能视为公司实机完成**：PR #9 的 `clean_cst(input, output)` 两路径零体积清理（模拟 CI 通过，真实 CST 删除尚待验证）。
- **已经有合成几何验证**：PR #10 的 OCP STEP 点包含判断，长方体内/外/表面测试已做；公司真实弹片 STEP 尚未验证。
- **尚未开始**：PySide6/VTK 三维查看器、完整 STEP ↔ CST Solid ID 可逆映射、稳定识别弹片/连接器、端到端自动赋材。

### 5. 下一次只做什么？

**只做 M2 的最小窗口**：

1. 从公司 CST 导出一个真实弹片的 STEP；
2. 使用 PySide6 + PyVistaQt/VTK 在独立 Windows 窗口显示并支持旋转、缩放、拾取；
3. 输入一个点 XYZ，在三维模型上标记该点，调用 OCP 给出 IN / ON / OUT；
4. 记录加载时间与使用感受。

**不在这个阶段开发整机导出、7,000 Solid 全量渲染、弹片自动分类或材料匹配。** 此验证通过后，才进入 M3 的自动导出与索引工作。

本节为待确认的研发计划；只有用户认可后才开始新增功能实现。
